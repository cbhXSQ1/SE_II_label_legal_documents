# 法律论证标注与教学支持系统 · 数据层接口约定

**组内评审稿 · v0.3 修订版 · 2026 年 11 月 25 日**

本文供 Spring Boot 功能层和 MySQL 数据层联调使用。功能层确定操作权限和可访问的数据范围，数据层按指定范围读取和保存记录。下表逐项列出功能层第五节声明的 13 个 Repository、112 个方法，包含重载。方法名、参数顺序和返回类型与仓库一致。对源文档仍有歧义的地方，末节列出需要双方确定的问题。[《功能层对下接口》本次对照版本](https://github.com/cbhXSQ1/SE_II_label_legal_documents/blob/5d92ddbd23a6a04282249016c65b9b5f90c61773/接口文档/后端/功能层/功能层对下接口.md)

## 一、通用读写约定

| 项目 | 功能层调用时可以依赖的行为 |
| --- | --- |
| Java 包与实体 | 接口在 `com.seii.legal.data.repository`，实体在 `com.seii.legal.data.entity`。参数为实体时传递对应的 Java 对象。公共分页类型在 `common.page`，身份和状态类型沿用 `common.enums`。 |
| 查询范围 | 功能层核定当前账号可访问的任务、班级或本人记录，再用对应的标识和查询条件调用方法。数据层将这些条件用于查询。例如按学生和练习查作答时，两项同时匹配。 |
| 单条、列表与分页 | `Optional<T>` 查无结果时返回 `Optional.empty()`，列表查无结果时返回空列表。`PageResult<T>` 的字段为 `records, total, page, size`，总页数由 `totalPages()` 给出。页码从 1 起，每页默认 20 条，`total` 按同一组筛选条件统计。 |
| 写入结果 | `String` 的含义取决于操作，例如新建返回记录标识，保存指南返回版本号，保存会话返回凭证。`void` 成功时无返回数据。失败时需让功能层取得具体原因。Java 异常类型见末节。 |
| 时间与轮次 | 时间参数按学校所在时区解释，Java 类型沿用 `LocalDateTime`。正式标注轮次使用 `RoundType.CUTTING` 和 `RoundType.STRUCTURED`。 |
| 请求重试 | 同一次提交重试应取得首次成功结果。独立发起的新提交仍要检查该轮是否已交。传递请求标识的方式见末节。 |

## 三、用一次仲裁比对联调

假设任务 `T1` 的文书 `D1` 在切分轮有甲、乙两份提交。功能层已核准当前仲裁员可读取本任务的提交。以下调用对应上游第七节的示例。[仲裁服务调用示例](https://github.com/cbhXSQ1/SE_II_label_legal_documents/blob/5d92ddbd23a6a04282249016c65b9b5f90c61773/接口文档/后端/功能层/功能层对下接口.md#L1529-L1562)

```java
List<Submission> submissions = annotationRepository.findSubmissions(
        "T1", "D1", RoundType.CUTTING, null);
```

- 预期读取甲、乙在该任务、该文书、该轮的提交。每条 `Submission` 携带 `submissionId, taskId, documentId, round, annotatorId, submittedAt, guideVersion, content, status, returnReason`。第四个参数传甲的账号时，只返回甲的匹配记录。
- 用另一项任务对同一份文书提交一条记录，再重复查询 `T1`。返回值仍应只包含 `T1` 的记录。指定范围内没有提交时，结果是空列表。
- 功能层使用所选记录的 `content` 进行比对。仲裁员选定结果后，功能层构造 `AdjudicationRecord`，调用 `adjudicationRepository.saveDecision(record)`。上游示例将新记录的 `decisionId` 留空，数据层保存后返回裁定标识。

## 四、MySQL 写入建议

以下是数据层拟提供的保存保证，供接口评审确认。

| 联调场景 | 数据层实现建议与验收方式 |
| --- | --- |
| 两次保存同一份草稿 | 对任务、文书和标注员的组合设置唯一约束。连续调用两次 `saveDraft` 后，`findDraft` 应读到第二次保存的内容，库中只有一份当前草稿。 |
| 两人同时导入同版指南 | 对版本号设置唯一约束。一个请求成功后，另一个请求得到“版本号已存在”，已保存版本的标签与原件引用保持完整。 |
| 确认最终版本 | `saveFinalVersion` 和 `confirmTask` 属于同一次最终确认时，参加同一个 Spring 事务。若任务状态更新失败，本次写入的最终版本也回滚。 |
| 学生转班 | 在一个事务内记录原班的移出时间和新班的加入时间。第二步写入失败时，两条成员记录都恢复到转班前。 |
| 网络超时后再次提交 | 请求标识的传递方式确定后，同一请求的标识、提交记录和成功结果在同一事务中保存。用原标识重试应取回原提交标识。 |

## 五、需要与功能层确认的问题

下列问题会影响方法怎样实现或调用。第二节保留仓库现有签名，表中建议供组内决定。

| 涉及接口 | 需要确定的约定 |
| --- | --- |
| 提交与重试 | 上游要求提交类接口携带请求标识，`saveSubmission(Submission)` 及已列出的 `Submission` 字段均未体现它，`saveAnswer(AnswerRecord)` 的实体字段也待明确。建议显式传递请求标识。同一请求返回原标识，新请求遇到本轮已有有效提交才报告重复。另外需确认判重是否包含任务 ID、退回后哪条记录参与判重，以及重开同种轮次如何定位历史记录。 |
| 阶段版本 | `saveElements`、`saveRelations` 均返回 `void`，下游分别要用 `elementVersionId` 和 `relationVersionId`。需要明确这两个标识在哪里生成、怎样取得。 |
| 中间结果与最终版本 | 上游第九节在切分裁定和结构化最终确认时都调用 `saveFinalVersion`，而 `findFinalVersion` 仅按任务和文书查询。需约定用什么字段区分统一切分与最终结果，以及仅确认切分时查询应返回什么。 |
| 文书重复与学生建号 | `DocumentRepository.save` 返回一个字符串，文字约定还要给出重复标记及已有文书标识。`createStudentAccount` 同样只返回字符串，首次建号还要求提供初始密码或设置密码链接。需确定各自的额外结果由哪个接口传回。 |
| 评分回写和阈值 | 第九节先保存作答再评分，`updateAnswerStatus` 的参数中没有得分。请确认自动评分结果怎样写回已有作答。`findWeakThreshold` 声明为 `Optional<Integer>`，文字要求默认 60%，需确认无记录时由数据层返回 `Optional.of(60)`，还是由调用方在空值时取 60。 |
| 查询范围 | 通用约定要求功能层传入授权范围。部分查询方法只接收对象 ID。建议逐个确认哪些调用在功能层先核定对象归属，哪些需要补充查询条件，特别是按 ID 读取提交关联数据时。 |
| 异常和缺省参数 | 部分写入会因重复、记录不存在或状态已变而失败，需统一让功能层取得原因的方式。未声明的可选筛选条件也需约定空值语义，例如 `NotificationRepository.find` 的 `read` 是否允许传 `null` 查询全部。 |
| 正式任务的文书数量 | `AnnotationTask.documentIds` 使用列表，审查后需求 FR-TASK-06 规定每个正式任务关联一份文书。建议保留列表签名，确认正式任务创建时只传一项。依据为《法律论证标注与教学支持系统 需求规格说明（审查后修改）》。 |
| 题目版本号 | `saveQuestionVersion` 以整数接收版本号、以字符串返回，而读取方法要求整数。需明确返回字符串代表版本号还是记录标识。 |
