# 功能层对页面接口（HTTP API 契约）

> 本文档是**前后端唯一接口契约**。前端 `src/api/` 与后端 `function.controller` 都按本文件实现。
> 它是 [功能层对下接口.md](功能层对下接口.md) 的补充：功能层往下调用规则层/数据层，往上通过本文档的 HTTP 接口服务页面。

## 一、通用约定

- 基路径：`/app`（前端 `baseURL` 已设为 `/app`；后端 `@RequestMapping("/app/...")`）。
- 身份凭证：除登录、申请、获取可选身份外，所有接口都带请求头 `Authorization`（登录凭证）。
- 统一响应：`AppResult<T> { success, message, data, allowedActions }`。
  - `success=false` 时前端统一 `ElMessage.error(message)` 并 reject；`success=true` 时前端取 `data`。
  - `allowedActions` 为下一步可做操作（用于渲染按钮），可留空数组。
- 分页：`PageResult<T> { records, total, page, size }`，`page` 从 1 开始，`size` 默认 20。
- 时间：`年-月-日 时:分:秒`（如 `2026-11-27 10:30:00`）。
- 百分比：差异度/一致度/得分/平均分保留 1 位小数，前端加 `%`。
- 防止重复提交：提交类接口（提交标注、提交作答、导出）请求体带 `requestId`（幂等键），同一 `requestId` 只落一条记录。
- 查询用 `GET`（query 参数），命令用 `POST`（JSON body）。例外：`POST /adjudication/compare` 沿用已有 controller 示例。

## 三、公共数据结构

### 3.1 会话与会话身份

```jsonc
// 登录/选择身份返回的 data
{
  "credential": "mock-…",     // 登录凭证，后续放 Authorization 头
  "accountId": "u1",
  "name": "李管理",
  "unit": "课程组",
  "system": "ADMIN",          // 当前系统，未选择时为 null
  "identity": "ADMIN",        // 当前身份，未选择时为 null
  "systemName": "管理后台",
  "identityName": "管理员",
  "single": true,             // 登录时：是否唯一身份（唯一则直接进入）
  "identity": null,           // 登录时：唯一身份则填该身份对象，否则 null
  "options": [                // 登录时：可选身份列表
    { "system": "ADMIN", "identity": "ADMIN", "systemName": "管理后台", "identityName": "管理员", "description": "…" }
  ]
}
```

系统枚举 `SystemType`：`ADMIN`（管理后台）/ `ANNOTATION`（普通标注系统）/ `TEACHING`（教学系统）。
身份枚举 `IdentityType`：`ADMIN` / `TEACHING_ADMIN` / `TASK_MANAGER` / `TEACHER` / `ANNOTATOR` / `STUDENT` / `ARBITER` / `EXPERT`。

### 3.2 标注内容（content，序列化为字符串存 Submission.content / Draft）

前端工作台保存/提交的标注内容，是一个结构化 JSON 对象；后端以 `String` 存入 `Submission.content`，读取时原样返回。

```jsonc
{
  "pieces":  [ { "id": "s1",  "text": "依法成立的合同，自成立时生效。" } ],
  "segments":[ { "id": "P1", "text": "依法成立的合同，自成立时生效。", "type": "GM-L" } ],
  "relations":[ { "id": "R1", "type": "J", "members": ["P4", "P5"], "formal": "J(P4, P5)" } ],
  "diagram": [
    {
      "id": "dg1", "title": "论证一",
      "nodes":   [ { "id": "P2", "x": 150, "y": 110 } ],
      "relNodes":[ { "id": "n1", "kind": "support|attack|plus|slash", "x": 145, "y": 205 } ],
      "edges":   [ { "from": "P4", "to": "n1", "arrow": false } ]
    }
  ]
}
```

- `segments[].type` 取值：非命题 `IS/AS/SS/JG/JD/Non-O`；命题 `SF/GF/SM/GM/SM-C/GM-L/GM-I/GM-U/GM-M/GM-O`。
- `relations[].type` 取值：`S`（支持）/ `A`（反对）/ `J`（组合）/ `M`（匹配）/ `I`（同一）。
- `diagram` 对应后端 `Diagram`（节点/边/布局）；`relNodes[].kind`：`support` 实心圆、`attack` 空心圆、`plus` 带“+”圆（J/M）、`slash` 矩形内“/”（I）。

### 3.3 差异项与一致度

```jsonc
// 比对/裁定/作答差异通用
{ "agreement": 97, "difference": 3, "items": [
  { "id": "d1", "type": "标签选择|标注边界|关系方向|图示结构", "object": "P4",
    "valueA": "SM", "valueB": "SF", "note": "判定说明" }
] }
```

```jsonc

// 学习材料 LearningMaterial
{ "id": "m1", "title": "指南讲解", "type": "指南讲解|标准样例|讲义|微课", "guideVersion": "v1.2",
  "points": ["kp1"], "className": "法学2501", "status": "草稿|已发布|已下架", "publishedAt": "…" }
// 题目 Question
{ "id": "q1", "type": "切割|要素标注|关系标注|综合标注|单选|多选|判断", "stem": "…", "difficulty": "中",
```

## 四、接口详情

### 1. 登录与身份

#### AUTH-01 登录
`POST /auth/login`
请求：`{ account, password }`
响应 data：会话对象（见 3.1，含 `single` / `options`）
说明：密码错误返回“账号或密码错误”；停用返回“账号已停用，请联系管理员”；无可进入身份返回“没有可进入的系统，请联系管理员”。
调用：`AccountRepository.findByAccount` · `AccountRule(状态判定)` · `IdentityRule.availableIdentities`

#### AUTH-02 选择身份
`POST /auth/select`
请求：`{ system, identity }`
响应 data：会话对象（更新后的 system/identity）
说明：账号没有该身份时返回失败。
调用：`IdentityRule.hasRole` · `SessionRepository.save`

#### AUTH-03 退出登录
`POST /auth/logout`
请求：`{}`
响应 data：`null`
调用：`SessionRepository.delete`

#### AUTH-04 账号申请
`POST /auth/apply`
请求：`{ name, unit, system, identity, studentNo?, teacherNo?, note }`
响应 data：`{ applicationId }`
调用：`ApplicationRepository.save`

#### AUTH-05 获取可选身份（用于“重新选择”）
`GET /auth/options`
响应 data：`{ name, options, currentSystem, currentIdentity }`
调用：`AccountRepository.findRoles` · `IdentityRule.availableIdentities`

## 五、前端对接说明

- 前端 `src/api/index.js` 按本文档的接口一一封装；`src/api/request.js` 已统一解包 `AppResult`、附带 `Authorization`、错误时 `ElMessage.error`。
- 后端 controller 只收请求与凭证，交给 service；service 先 `requireSession` → `IdentityRule` 判定身份与数据范围 → 调 rule/data → 组装 `AppResult`（示例见《功能层对下接口》第七章）。
- 新增/修改接口时，先改本文档，再同步两端，保证三处一致：文档、`src/api/`、后端 controller。
